Endpoint S3 SCM Plugin

The Endpoint S3 SCM plugin checks out ZIP archives from S3-compatible object storage into the Jenkins workspace. It supports prefix-based discovery of the latest archive, direct download of an exact key, checksum verification, failover across multiple S3 locations, and polling for change detection.

Plugin version: 1.2.0  |   Requires Jenkins: 2.414.3+

Configuration hierarchy

S3 source locations and checkout settings are not embedded in the job definition. They are resolved from the nearest enclosing scope and merged in this order:

  1. Folder settings — Folder → Configure → Endpoint S3 SCM Settings
  2. Global settings — Manage Jenkins → System → Endpoint S3 SCM — Global Settings

Folder locations are tried first (in priority order). Global locations are appended as fallback sources. Retry, strip, and checksum settings are taken from the folder if the folder has at least one location configured; otherwise from global settings.

Operating modes

Prefix mode (default)

When Directory / Prefix does not end with .zip (e.g. releases/ or apps/backend), the plugin lists all objects under that prefix, filters for non-empty .zip files, and selects the one with the latest lastModified timestamp.

Exact ZIP mode

When Directory / Prefix ends with .zip (case-insensitive, e.g. releases/app-2.0.zip), the plugin issues a single HEAD request to verify the object exists, then downloads it directly — no listing is performed. This mode is also used for polling.

Pipeline usage

Only prefix (and optionally targetDirectory) are specified in the pipeline. S3 locations come from the folder or global configuration.

Latest ZIP from prefix

checkout([$class: 'EndpointS3SCM', prefix: 'releases/myapp/'])

Exact ZIP key

checkout([$class: 'EndpointS3SCM', prefix: 'releases/myapp/app-2.0.zip'])

Extract into a subdirectory

checkout([$class: 'EndpointS3SCM', prefix: 'shared/configs/', targetDirectory: 'config'])

Checksum verification

After downloading the archive the plugin searches for a companion checksum file at <key>.sha512 (preferred) or <key>.sha256. If the file is found the hash is verified; if neither file exists the download is accepted as-is and a warning is logged. Set Skip checksum verification to suppress the warning entirely.

Expected format — a single hex digest on the first line (with optional filename suffix):

a190edabd05e933c5bf... app-2.0.zip

Polling

The plugin supports SCM polling. On each poll it resolves the same prefix/key and compares the result against the last build's revision state (key + lastModified timestamp). A build is triggered when:

  • a new ZIP key appears under the prefix (prefix mode), or
  • the existing object has a newer lastModified timestamp (both modes).

If all S3 sources are unreachable during a poll, NO_CHANGES is returned (conservative — does not trigger a false build).

Troubleshooting

ErrorCauseSolution
No ZIP files found in prefix No non-empty .zip objects found under the configured prefix. Verify the prefix value and confirm archives are uploaded to that location.
No ZIP file found at key Exact ZIP mode: the specified object key does not exist in the bucket. Check the full key path and bucket name.
All S3 sources failed Every configured location failed. Check endpoints, buckets, credentials, network, and source priorities.
Archive too large Object size exceeds the 1 GB built-in limit. Reduce the archive size.
Checksum mismatch Downloaded archive does not match the companion checksum file. Re-upload the archive (and its checksum file). Check for upload corruption.
AccessDenied / HTTP 403 Credentials lack permission to list or read objects. Grant s3:ListBucket and s3:GetObject on the bucket.
Connection refused / host unreachable Endpoint URL or network configuration is wrong. Verify endpoint, port, DNS, proxy and firewall settings.
Global location not used as fallback After a package upgrade the global config XML may reference the old class name and load as empty. Re-save Manage Jenkins → System → Endpoint S3 SCM — Global Settings to write the config under the current class name.
Workspace empty in pipeline stages The automatic @script checkout populates only the Jenkinsfile workspace, not the build workspace. Add an explicit checkout scm or checkout([$class: 'EndpointS3SCM', prefix: '...']) inside a pipeline stage.
